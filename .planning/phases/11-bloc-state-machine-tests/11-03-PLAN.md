SettingsBloc is the most complex BLoC in the codebase: 7 constructor-injected use cases, one BiometricService dependency, side-effects through LocaleManager, and 4 sibling BLoC calls via GetIt in the ResetAllDataRequested handler.

LocaleManager is a pure Dart singleton (confirmed: lib/core/utils/locale_manager.dart reads no platform channels — it only sets intl.Intl.defaultLocale and a private _currentLocale field). No TestWidgetsFlutterBinding.ensureInitialized() is needed. LocaleManager._instance persists across tests; this is safe because it only affects locale formatting, not BLoC state.

BiometricService wraps local_auth. It must be stubbed — never invoke the real implementation in unit tests. The stub implements the two-method interface and exposes an authenticateResult: bool field to control test outcomes.

All seven use cases implement UseCase<T,P> (settings use cases follow the standard interface). Stubs follow Pattern A (void return) or Pattern B (non-void return).
